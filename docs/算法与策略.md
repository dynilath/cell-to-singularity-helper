# 算法与策略

本文记录助手的规划目标、在线/离线策略、搜索算法和基准结果。使用说明见 [使用说明](使用说明.md)。

## 目标选择

规划器会按当前状态重新选择目标：

1. 如果存在已解锁、尚未拥有首台的工厂：
   - 目标 = 最快点出第一个这样的新工厂。
2. 否则：
   - 目标 = 完成全部未购买升级。

追求新工厂首台时，搜索仍可顺路购买已解锁升级；只要产出提升能缩短攒钱时间，就会纳入路径。

### 门禁兜底

如果完整目标被前置链锁死，搜索可能拿不到完整方案。此时会反向遍历锁定工厂/升级的前置：

- 找到最近的可执行前置；
- 只规划到它：
  - 升级 → 先买该升级；
  - 工厂首台 → 先买出首台；
  - 工厂数量门槛 → 先补到所需数量；
- 买完这一段后重新规划。

兜底计划标记为 `unlock`，界面显示为“先买「X」”，不会再显示“完成全部 N 个升级”。

如果反向遍历也找不到可执行前置，说明数据存在缺失或循环前置，仍然会报无路径。

## 在线策略

在线方案按在线产出计算下一次行动时间：

```text
计划剩余时间 = 还差资源 ÷ 在线总产出
```

## 离线策略

离线收益倍率有两个用途：

- 提醒等待：点提醒后离开游戏，提醒按倍率提前；
- 「离线攒钱」策略：计划把连续动作合并成离线段，离线期间收入按倍率累计，段内不买工厂。

```text
离线攒钱剩余时间 = 还差资源 ÷（在线总产出 × 离线收益倍率）
```

离线方案时间已经按倍率累计，提醒时不会再除一次。

### 3 分钟块

离线等待只按**完整的 3 分钟块**计算：

```text
180 / 360 / 540 … 秒
```

如果精确攒到目标所需时间不是 3 分钟倍数，这一整段改走在线等待；不会把带零头的时间伪装成离线收益。若离线 3 分钟块比在线等待更慢，也直接走在线。

3 分钟来自实际手算经验（常见 12/15/17 分钟档位）；低于 3 分钟的零碎等待一般直接不等。

### 分段与立即购买

离线策略按段生成：每段先用当前状态重新搜索，买完这一段再从新状态重新规划。

- 已经买得起的下一步会立即购买，不会为了凑更长的离线批次而推迟到等待结束；
- 会改变产出的购买默认不提前合并；
- 同一工厂的连续购买、或“一次升级 + 紧随其后的工厂购买”，只有在模拟确认不更慢时才合并；
- 因此会出现“先升级、再工厂、再升级”的交错，不会把最初的一长串升级锁死。

### 3 分钟检查点

在等待第一个较长动作的途中，每到 3 分钟检查一次资源是否已经能买工厂；如果能，就尝试“返回买一台工厂 → 重新规划剩余部分”。只有总时间不增加时才采用。

当前只实现第一个长等待的检查点插入，尚未扩展成完整的“等待动作最短路径”搜索。

时间表会把离线段显示为“离线 X 分钟（离线收入广告 ×2）· 回来后连续购买”，随后才是真正的购买操作。

## 搜索

规划器用**状态空间搜索（A\*）**寻找购买工厂/升级的最短时间路径：

- 每个状态可以攒钱买任意一个工厂或升级；
- 按总耗时排序，考虑“先多买工厂、稍晚升级，但后续更快”；
- 贪心路径作为搜索上界；
- 搜索节点预算耗尽时退回贪心结果。

方案会按当前实际资源重新计算。提前打开时资源低于原计划预期，等待变长，先补工厂可能从“不划算”变成“更划算”，下一步会改买工厂；这是按新状态重新优化，不代表上次计算错误。

## 算法基准

`pnpm bench` 在几个小状态上对比：

- 当前生产规划器；
- 事件图 Dijkstra（小状态参考，带支配剪枝和节点上限）；
- 实验性 A*（简单启发式，不保证最优）。

在线结果：

| 场景 | 当前 vs Dijkstra |
|---|---:|
| 简单升级 | 0% |
| 先补工厂再升级 | 0% |
| 两台工厂/两个升级 | +3.7% |
| 肺：已买得起第一台 | +81.1% |
| 多资源工厂 | +15.3% |
| 前置解锁链 | +36.3% |

离线结果：

| 场景 | 当前 vs Dijkstra |
|---|---:|
| 简单升级 | 0% |
| 先补工厂再升级 | +43.9% |
| 两台工厂/两个升级 | +54.1% |
| 肺：已买得起第一台 | +64.8% |
| 多资源工厂 | +63.1% |
| 前置解锁链 | +47.2% |

Dijkstra 在“多资源工厂”场景约需 1.7 万节点/0.8 秒，直接替换生产规划器太慢。基准用于量化启发式损失，并为后续“小状态精确搜索 + 大状态启发式”的混合方案提供对照。

### 前置解锁分段

`bench` 还会从 `requires`/目标工厂关系里提取关卡，按前置排序，逐关运行 Dijkstra：

```text
当前状态 → 第 1 关 Dijkstra → 第 2 关 Dijkstra → … → 最终目标
```

“前置解锁链”场景：

| 策略 | 当前 | 全局 Dijkstra | 分段 Dijkstra |
|---|---:|---:|---:|
| 在线 | 15.84m | 11.62m / 1757 节点 | 12.36m / 624 节点 |
| 离线 | 11.71m | 7.96m / 990 节点 | 8.36m / 214 节点 |

分段把搜索节点数降到约 1/3–1/5，代价是 5%–6% 的时间损失。原因是原型固定了关卡顺序，并且每关只保留第一个达标状态。

## 已知限制

- 规划器使用有预算的 A* 状态搜索；复杂状态、搜索预算耗尽时退回贪心上界，不保证数学最优。
- 完整目标被前置锁死时，只规划“最近可执行前置”这一段；买完后重新规划，不会强行生成无法完成的长计划。
- 当前门禁兜底是单段计划，不是完整的关卡分段搜索。
- 3 分钟检查点目前只覆盖第一个长等待。
- 每个工厂的贡献依赖“已拥有数量”，需要如实填写；未列出的旧产能放在资源的“基础产出”里。
- 至少保留一个资源和一个工厂；被工厂/升级引用的资源不能删除。
- 旧版分类级计划不会迁移（数据结构已变化），迁移后需要重新规划。
