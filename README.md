# 探索活动助手 · Cell to Singularity

一个纯前端、可离线使用的探索活动规划工具：多资源、多工厂、多升级，算出先买什么、什么时候点升级，并在到点时提醒。

构建后只有一个 `dist/index.html`，双击即可使用，不需要服务器。

## 快速开始

1. 在 **① 资源** 里添加资源：选一个预设 emoji，填当前数量、基础产出和总计产出。资源没有名称，只靠图标区分。右上角可选择 **全局广告倍率 ×1/×2/×4**，它乘在所有工厂产出上，工厂输入的是**不含该倍率的基准单台产出**。
   - 总计产出 = 基础产出 + 有效工厂贡献（已乘升级倍率和全局广告倍率）；
   - 输入基础产出会自动算出总计；直接修改总计会反推出基础产出（总计减去工厂贡献）。
2. 在 **② 升级** 里填目标工厂、产出倍率、升级价格（右侧图标是花费资源）；买下后目标工厂的产出会乘以该倍率。未满足前置条件的升级会锁定，可勾选 **隐藏未解锁** 过滤掉，开关会持久保存。
3. 在 **③ 工厂** 里填每个工厂（单行四项）：
   - 标题行显示工厂序号、快速结算、当前贡献和删除；已拥有数量为 0 的工厂自动视为新工厂；
   - 已拥有数量、下一台价格、单台产出/秒、价格增长倍率（留空用全局倍率）；
   - 价格输入右侧的图标是价格资源，产出输入右侧的图标是产出资源（可以不同）；
   - 数据不完整/无效的工厂会自动灰显并忽略：不参与产出和规划，快速结算按钮也不可用。
4. **④ 最优方案** 会给出下一步、完成时刻和完整时间表；可切换「在线最快 / 离线攒钱」策略，也可点「提醒我」或「逐步执行」。

## 预设导入

在右下角 **⚙️ 悬浮球菜单** 里点 **📥 引入预设…**，会先选择具体预设，再载入内置的「微型探索 · 面对恐惧」数据。

- 预设文档数值以**声望 2**为基准；导入时可输入当前声望等级和徽章加成。
- 文档产出包含 **全局广告 ×4**：导入时先除以 4 存成基准单台产出，再按声望和徽章换算；请在页面顶部选择你实际的全局广告倍率（若为 ×4，则恢复文档有效产出）。
- 声望：每升一级，收入 ×2、成本 ×4（从声望 1 起累乘）。
- 徽章：只增加收入，以 5% 为单位，例如 +10% 表示收入再乘 1.1。
- 导入会**重置**当前资源、工厂、单台产出、升级、计划和提醒，不能撤销。
- 工厂默认从 0 台开始，请按游戏实际已拥有数量填写。单台价格按声望/徽章换算，单台产出按「文档值 ÷ 全局广告4 × 声望和徽章」写入，并按当前「数字显示格式」显示。
- 面对恐惧的三个工厂成本增长倍率固定为 **1.15**。
- 文档里的“解锁条件”会转成前置条件：工厂/升级需要先拥有指定工厂或购买指定升级；工厂前置要求该工厂**至少已拥有 1 台**。未满足时显示锁定、不能购买，规划器也不会把它排进时间表。
- 当前实现暂不参与规划：篝火的「点击收益 +1」。

## 资源与产出

所有资源共用同一张规划表。工厂的当前贡献为：

```text
工厂贡献 = 已拥有数量 × 单台产出 × 升级倍率 × 全局广告倍率
资源总产出 = 基础产出 + 该资源下所有工厂贡献之和
```

单台产出和升级倍率都按基准值保存；全局广告倍率是顶部的独立选项，改变它会立即重算产出和计划。

购买升级时会直接把倍率乘进目标工厂的「单台产出」，没有隐藏乘数；填错了直接改单台产出即可。

「在线最快」方案按在线产出计算下次行动时间，不乘离线收益倍率：

```text
计划剩余时间 = 还差资源 ÷ 在线总产出
```

**离线收益倍率**有两个用途：

- 提醒等待：默认点提醒后离开游戏，提醒会按倍率提前；
- 「离线攒钱」策略：计划本身把若干连续动作合并成离线段，离线期间收入按倍率累计，但不会在段内买工厂，因此没有阶梯增产；回到游戏后连续买完这一段。

离线攒钱会从 1 台到整段尝试不同段长：先找最短总时长；只有当合并不比最短方案更慢时，才用合并减少离线段数（减少离开/回来的次数）。多资源时合并可能被迫等更慢的资源，这种更慢的合并会被淘汰；会改变产出的动作也不会被提前合并。

离线等待只按**完整的 3 分钟块**计算，也就是 `180 / 360 / 540…` 秒；如果精确攒到目标所需的时间不是 3 分钟倍数，这一整段改走在线等待，不会把带零头的时间伪装成离线收益。若离线 3 分钟块比在线等待更慢，也会直接走在线。

```text
离线攒钱剩余时间 = 还差资源 ÷（在线总产出 × 离线收益倍率）
```

离线方案的时间已经按倍率累计过，提醒时不会再除一次。修改离线倍率会重算离线方案；在线方案不受影响。

离线策略按段生成：每段先用当前状态重新搜索动作顺序，买完这一段后再从新状态重新规划。**已经买得起的下一步会立即购买**，不会为了凑一个更长的离线批次而推迟到等待结束；买完后再按新产出重新规划。会改变产出的购买（工厂、倍率≠1 的升级）默认不提前合并，买完一个就立即重算；但如果第一项是升级、后面紧跟一串工厂购买，规划会尝试把这串工厂也并入升级前的同一次离线等待，让工厂资源同样享受离线加成。只有模拟出来确实不更慢时才会采用这种合并。

离线策略还会尝试 **3 分钟检查点**：在等待第一个较长动作的途中，每到 3 分钟就看资源是否已经能买工厂；如果能，就尝试「返回买一台工厂 → 重新规划剩余部分」。这只用于让资源过线后的策略更稳定，只有总时间不增加时才会采用。3 分钟来自实际手算经验（常见 12/15/17 分钟档位）；低于 3 分钟的零碎等待一般直接不等，交给普通在线等待处理。当前先实现第一个长等待的检查点插入，尚未扩展成完整的“等待动作最短路径”搜索。

因此会出现「先升级，再工厂，再升级」的交错，不会把最初的一长串升级锁死。段内动作被购买时，会保留剩余段的计划，不会在买第一个时立刻改掉后面的步骤。

时间表会把每一段显示为一行「离线 X 分钟（离线收入广告 ×2）· 回来后连续购买」，随后才是真正的「买 xxx」操作；离线攒钱本身不会自动购买。**离线等待只按 3 分钟整数倍计算**；不足 3 分钟或带零头的精确等待按在线等待处理，不会显示成离线段。

## 工厂、升级与新工厂

- **快速结算**「买1/5/10个」：扣除连续购买的总价（价格按增长倍率递增），增加已拥有数量，更新下一台价格。
- **未解锁工厂**：拥有数量不可直接编辑，普通点「买X个」也不会购买；按住 Ctrl 点「买X个」可强制购买并解锁（资源不足时清零）。
- **按住 Ctrl 强制购买**：点「买X个」时如果资源不足，仍会增加工厂并把支付资源清零；按住 Ctrl 期间这些按钮会变色提示。
- **购买升级**：扣除对应资源，把倍率直接乘到目标工厂的单台产出，然后从列表删除升级；工厂贡献立即更新。按住 Ctrl 点购买可在资源不足时强制购买，并把支付资源清零。
- **删除升级**：只移除未购买的升级，不扣资源、不应用倍率。
- 没有额外的隐藏升级乘数。活动更新后如果重新填数，直接检查/修改工厂的单台产出即可；购买错了也可以直接改单台产出。
- **新工厂**：已拥有数量为 0 的工厂自动视为新工厂，规划目标会优先变成“最快点出第一个新工厂的首台”。买到首台后它不再是新工厂，对应升级解锁，目标切回“完成全部升级”。如果所有 0 台工厂都被前置条件锁住，规划会先回退到“完成升级”，用升级链解锁工厂，再在重新规划时切回新工厂。追求新工厂首台时，搜索仍可顺路购买已解锁升级——只要升级带来的产出提升能缩短攒钱时间。
- 新工厂还没买首台时，指向它的升级不能购买，按钮会显示“需先买目标工厂首台”。
- 规划目标：
  - 存在尚未买首台的新工厂 → 最快点出第一个新工厂；
  - 否则 → 最快完成所有未购买升级。

规划器用**状态空间搜索（A\*）**找“购买工厂 / 购买升级”的最短时间路径：每个状态都可以选择攒钱买任意一个工厂或升级，搜索按总耗时排序，因此会考虑“先多买几个工厂、稍晚一点升级，但后续更快”这类跨多个升级的组合。贪心路径作为搜索上界和搜索预算耗尽时的兜底。

方案会按当前实际资源重新计算。若提前打开时资源低于原计划当时的预期，剩余等待变长，先买工厂可能从“不划算”变成“更划算”，下一步会改买工厂；这是按新状态重新优化，不代表上一次计算错误。若当前资源高于原计划当时的状态，却仍出现这种反向变化，才应检查产出/费用数据是否填错。

## 数字显示格式

右下角 **⚙️ 悬浮球菜单** 提供数字显示格式下拉、预设导入和倍率助手：

- **英文后缀**：`1.23K / 1.23M / 1.23B / 1.23T / 1.23Qa…`
- **中文单位**：`1.23万 / 1.23亿 / 1.23兆 / 1.23京…`
- **科学计数法**：`1.23e12 / 2.33e14`

带单位时保留 3 位有效数字；超出范围自动用科学计数法。切换会转换所有资源的数量、基础产出、工厂价格/产出和升级价格；已拥有数量、倍率不转换。设置保存在 `cts_notation`。

## 快捷操作与键盘

- 工厂快速结算、删除、拖动手柄都不进入 Tab 顺序；正常填写不会被它们打断。
- 资源图标下拉、全局/工厂增长倍率、升级倍率和离线收益倍率也不进入 Tab 顺序，用鼠标点选即可。
- 拖动手柄可调整工厂顺序，顺序变化会保存并重新规划。
- 「逐步执行」中每点一次「完成此步」会把该步的购买应用到当前数据（扣资源、加拥有数或买升级），然后推进到下一步。
- 手动用「买X个」或「购买」也会记录到数据并自动重算。数据编辑和计划外购买统一走 **300ms 防抖**：旧计划先作废，300ms 内的连续操作合并成一次重算，避免连续点击时每次都卡住；计划内的连续步骤仍直接推进，不触发重算。**资源总量输入是权威快照**：重算直接使用你输入的数量，不叠加防抖等待期间自动增长的产出；即使收入很高，也不会把这 300ms 的产出混进计划。同一组数据重复编辑回来会得到同样的计划。

## 提醒

- 点「提醒我」= 以当前数据为快照，开始为下一步倒计时；刷新或重新打开页面后倒计时继续。
- 离线收入广告翻倍：启用后整段离线收入 ×2；离线方案的计划时间、以及在线/离线方案的提醒等待都会按 2× 缩短。不会再额外叠加半程提醒，否则会变成 1/4 时间。
- 到点提醒 = 页面横幅 + 蜂鸣 + 标题闪烁；若浏览器通知已授权，还会弹系统通知。
- 右上角「提醒」抽屉可暂停、恢复、重新计时或取消当前规划的提醒。

## 数据与迁移

- 当前存档键：`cts_data_v6`；资源（含 emoji）、工厂、升级、计划和提醒都在里面。
- 旧版 v5 的多个分类会合并成一个数据集：分类变成资源，分类 emoji 变成资源 emoji，工厂/升级引用会重映射；旧的分类级计划/提醒不再适用，需要重新规划。
- 旧版 v4/v3 的固定三个槽位本来就是不同资源：每个非空槽位迁移成一个资源，原工厂跟随该资源，原来的单一升级迁移为目标为该资源第一个工厂、倍率 1 的升级；活动槽位的提醒会保留。
- 旧版 v2 的单组数据迁移成一个资源。
- 设置键：`cts_volume`、`cts_half`、`cts_notation`、`cts_offline_rate`。

## 算法基准

`npm run bench` 会在几个小状态上对比：

- 当前生产规划器；
- 事件图 Dijkstra（小状态参考，带支配剪枝和节点上限）；
- 一个实验性 A*（简单启发式，不保证最优）。

当前结果里，简单状态通常已经最优，但更复杂的工厂投资/多资源场景存在明显差距：

| 场景 | 当前 vs Dijkstra（在线） | 当前 vs Dijkstra（离线） |
|---|---:|---:|
| 简单升级 | 0% | 0% |
| 先补工厂再升级 | 0% | +43.9% |
| 两台工厂/两个升级 | +3.7% | +54.1% |
| 肺：已买得起第一台 | +81.1% | +64.8% |
| 多资源工厂 | +15.3% | +63.1% |
| 前置解锁链 | +36.3% | +47.2% |

Dijkstra 在“多资源工厂”场景需要约 1.7 万节点/0.8 秒，直接替换生产规划器会太慢。基准的用途是量化启发式损失，并给后续“小状态精确搜索 + 大状态启发式”的混合方案提供对照。

### 前置解锁分段

`bench` 还会从 `requires`/目标工厂关系里提取“关卡”，按前置关系排序，然后逐关运行 Dijkstra：

```text
当前状态 → 第 1 关 Dijkstra → 第 2 关 Dijkstra → … → 最终目标
```

“前置解锁链”场景的结果：

| 策略 | 当前 | 全局 Dijkstra | 分段 Dijkstra |
|---|---:|---:|---:|
| 在线 | 15.84m | 11.62m / 1757 节点 | 12.36m / 624 节点 |
| 离线 | 11.71m | 7.96m / 990 节点 | 8.36m / 214 节点 |

分段把搜索节点数降到约 **1/3–1/5**，代价是 5%–6% 的时间损失。原因是当前原型固定了关卡顺序，并且每关只保留第一个达标状态；后续可以在关卡处保留“时间 + 资源”的 Pareto 前沿，或让分支关卡顺序参与搜索，以换回最优性。

## 已知限制

- 规划器使用有预算的 A* 状态搜索；状态特别多、搜索预算耗尽时会退回贪心上界，因此极复杂配置下不保证数学最优。
- 每个工厂的当前贡献依赖“已拥有数量”，需要如实填写；不列出的旧产能可放在资源的“基础产出”里。
- 至少保留一个资源和一个工厂；被工厂/升级引用的资源不能删除。
- 旧版分类级计划不会迁移（数据结构已变化），迁移后需要重新规划。
