# 算法与策略

本文记录助手的规划目标、状态空间搜索和离线等待规则。使用说明见 [使用说明](使用说明.md)。

## 唯一策略：状态空间搜索

界面不再区分「在线最快 / 离线攒钱」。每次规划都只做一件事：

```text
选一个当前分段目标
→ 在该目标上做状态空间搜索
→ 买完这一段后重新选目标、重新搜索
```

因此一个计划显示的是“当前段”，不是未来全部几十步。

## 目标选择

### 有锁定项时

从所有锁定工厂/升级反向遍历前置，收集“已经可以执行、只差购买”的前置节点：

- 升级 → 目标为购买该升级；
- 工厂首台 → 目标为买出首台；
- 工厂数量门槛 → 目标为补到所需数量。

多个候选时选预计等待时间最短的一个。买完这一段后重新规划，不会一次生成整条长链。

### 没有锁定项时

在该状态下选一个可执行目标：

- 还有 0 台的可执行工厂时，优先作为分段目标；
- 否则选一个未购买的可执行升级；
- 所有工厂至少 1 台且升级全部买完，规划完成。

## 状态空间搜索

每个搜索状态包含：

```text
资源数量
每个工厂的已拥有数量、下一台价格
已购买升级
```

动作是“等钱 → 买一个工厂/升级”。搜索按累计时间展开，达到当前分段目标即停止。

为了不把无关的几十个升级全部展开，当前分段使用同一套资源链闭包收集动作：

1. 从目标花费的资源开始；
2. 加入所有产出这些资源的工厂；
3. 加入这些工厂对应的可用升级；
4. 把新加入工厂/升级的成本资源也加入目标资源；
5. 重复 2–4，直到不再增加，或达到 8 层限制。

目标升级和目标工厂本身始终保留。这样：

- 目标要蓝色、骨骼产蓝色、骨骼要红色时，生产红色的心脏也会进入；
- 能放大骨骼产出的“骨髓”也会进入；
- 不再按“成本资源必须等于产出资源”过滤；
- 不再维护多套不同的“相关工厂/相关升级”特判。

如果完整闭包仍然太大，搜索会在 20,000 个状态预算内返回当前最优目标路径；不会因为预算耗尽直接返回空计划。

搜索不使用“开局预购种子”。每个候选动作在展开前会模拟：

```text
等待时间 + 购买后的目标剩余等待
```

只有它比当前直接等目标更短（至少缩短 0.1% 或 1 秒）时才进入搜索；目标动作本身始终保留。这样：

- 买肌肉、皮下组织这类能明显缩短目标的投资会被保留；
- 买一个大脑只让总时间缩短几毫秒的“微优化”会被过滤，不会反复推荐；
- 搜索仍然是真正的状态空间搜索，不会先把一批工厂/升级强行买掉再递归规划。

搜索分两次执行相同目标：

1. **直接生产者**：只包含直接产出目标资源的工厂/升级，规模小、速度快；
2. **完整资源链**：加入间接工厂，用于处理“先买产红色的心脏，才能买产蓝色的骨骼”这类链路。

两次结果取总时间更短者，避免完整链路的分支把直接生产者的更优解挤出搜索预算。

搜索使用有预算的 A*，状态数超过上限时返回当前最好结果。当前预算是 20,000 个状态，分段目标通常远低于这个规模。

## 在线等待与 3 分钟离线块

每个购买动作同时尝试两种等待：

```text
在线等待 = 还差资源 ÷ 在线产出

离线原始时间 = 还差资源 ÷（在线产出 × 离线收益倍率）
离线等待 = 向上取整到 180 秒的整数倍
```

两种等待都作为状态边进入搜索，由搜索选择总时间更短者。

离线等待只按完整的 3 分钟块计算：

```text
180 / 360 / 540 … 秒
```

带零头的精确等待不会伪装成离线收益；如果离线块比在线等待更慢，也会走在线。

在计划里，离线段会显示为“先离线攒 X 分钟”，并标记该步骤已经在离线倍率下计算过；提醒时不会再次除以离线倍率。

## 工厂投资

不能用 `price / unit` 判断工厂是否值得买，因为成本资源和产出资源可能不同。

搜索中的工厂动作直接模拟：

```text
等待购买工厂的资源
→ 买下工厂
→ 工厂产出加入总产出
→ 再继续等待目标资源
```

因此骨骼这种“花红色资源、产出蓝色资源、单台提升很大”的工厂，会和“直接攒骨头升级”比较总时间，而不是比较不同资源的单价。

## 已知限制

- 分段搜索只优化当前目标，不保证全局多目标最优；买完会重新规划。
- 搜索预算耗尽时返回当前最好结果。
- 当前只展开与当前目标相关的工厂，不会为后续目标提前投资；目标工厂和成本/产出资源不同的跨资源工厂都会保留。
- 目标数量门槛（例如 5 台内分泌）会保留，但搜索可能分多次购买，直到达到数量。
- 旧版分类级计划不会迁移，迁移后需要重新规划。
